# Q4V1: экспериментальный векторный формат на 3 бита

Это отдельный исследовательский формат, не новый режим `.vtq`. Вместо треллиса четыре соседних веса после вращения получают один восьмибитный индекс в таблице из 256 четырёхмерных **модулей** и четыре независимых знака. Таким образом 1024 байта таблицы задают до 4096 знаковых векторов. На уровне отдельного веса нет требования, чтобы все координаты имели одни и те же восемь уровней. Поиск при создании и чтение готового файла независимы.

## Бинарная раскладка одной матрицы

Числа little-endian, без выравнивающих байтов. `K` кратно 256.

1. `Q4V1` (4 байта), `M` и `K` (`uint32`). Далее таблица `[256,4]` (`uint8`, единица `1/64`), масштабы строк `d[M]` и знаковые предобусловливатели столбцов `suh[K]` (оба `fp16`).
2. Для каждой строки и последовательного блока из 256 столбцов — ровно **101 байт**:

| Смещение в блоке | Данные |
| --- | --- |
| 0–63 | 64 индекса в таблице, по одному на четвёрку |
| 64–95 | 256 знаков: младший бит байта соответствует первому весу, `1` означает минус |
| 96–99 | 16 двухбитных индексов усиления, младшие биты первыми, по индексу на 16 весов |
| 100 | `u`, масштаб блока (0 означает полностью нулевой блок) |

Для позиции `j` в блоке модуль равен `book[id[j//4],j%4] / 64`. Декодер применяет знак и умножает на `gain[g[j//16]] * d[row] * u/128`, где `gain = [0.6875, 0.875, 1.0625, 1.375]`. После всех блоков — обратное вращение `apply_vtq_rot(..., transpose=True)` и умножение столбцов на `suh`. Длина файла точно `1036 + 2*(M+K) + 101*M*(K/256)` байт.

## Два кодировщика, один декодер

- **Q4V** использует только диагональ входной ковариации. В Triton-ядре каждый тайл кодируется независимо. Для каждого из четырёх усилений ячейка сетки `16⁴` предлагает четыре индекса-кандидата; ядро сравнивает их *по настоящему вектору*, выбирает общее усиление с минимальной суммой ошибок для 16 весов и уточняет `u`. Сетка (256 КиБ) нужна только кодировщику и не записывается в файл.
- **Q4V-H** использует полную калибровочную ковариацию: переносит ошибку в ещё не закодированные 256-столбцовые блоки, затем подбирает `d` и `suh` по взвешенной ошибке реконструкции. Формат, длина файла и код декодирования не меняются.
- Общая таблица обучена только на синтетических гауссовых векторах. Для воспроизводимости используется [замороженная таблица](../../results/q4v_book.bin), а не переобучение на проверяемых слоях.

## Как проверялось

[Результаты Colab G4](../../results/q4v_g4_modes.json): все 48 матриц GPT-2 small (84 934 656 весов). Контроль — действующий `VTQ_300` с его собственным кодировщиком. У обоих форматов одинаковый объём тайлов и масштабов, **3.18403 бит/вес** на этих матрицах; фактические размеры отдельных файлов с заголовками приведены отдельно в JSON. У эталонного VTQ-писателя в этом тесте резерв заголовка 4096 байт; разница в заголовках не является выигрышем в точности или в плотности тайлов.

Калибровка и проверка — по 16 непересекающихся контекстов по 128 токенов из разных половин WikiText-2 test. Проверочные веса для обоих форматов получены **декодированием сериализованных байтов**. KLD считается от BF16; нормы, смещения, эмбеддинги и выходная голова остаются BF16. Таймер CUDA синхронизирован; прогрев считается отдельно. Время кодирования не включает получение статистик активаций, построение сетки, перенос весов на GPU, запись на диск и чтение. `peak_extra_bytes` — дополнительная выделенная PyTorch VRAM сверх состояния перед вызовом, а не потребление всего процесса. `reference_decode_s` относится к эталонному распаковщику с NumPy и вращением на GPU, **не** к инференсу AVX2/GPU GEMV.

```sh
python -m unittest -v src.test_q4v
python -m src.bench_q4v --model /path/to/gpt2 --output results/q4v_g4_modes.json
```

**Вывод:** независимые тайлы выгодны для быстрого создания кванта; коррекция ошибки в Q4V-H существенно снижает KLD, но на GPT-2 оба режима пока уступают VTQ при равном полезном битрейте. Не заменять VTQ по умолчанию. Следующий содержательный тест для качества — обратная связь внутри 256-столбцового блока, а не только между блоками; затем нужна независимая проверка на другой архитектуре.
