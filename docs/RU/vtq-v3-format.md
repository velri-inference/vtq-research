# Спецификация формата и квантователя VTQ v3 (`.vtq`, `VERSION = 3`)

Документ описывает бинарный формат квантования весов **VTQ v3** (`MAGIC = b"VTQ\0"`, `VERSION = 3`), эталонный декодер и контейнер [`src/vtq_v3_format.py`](../../src/vtq_v3_format.py), квантователь [`src/vtq_v3.py`](../../src/vtq_v3.py), ядра декодирования для CPU AVX2 ([`src/cpu/vtq3_avx2_bench.c`](../../src/cpu/vtq3_avx2_bench.c)) и GPU Blackwell `sm_120` ([`src/cuda/vtq3_matvec_bench.cu`](../../src/cuda/vtq3_matvec_bench.cu)), а также результаты сквозных бенчмарков скорости и качества (`KLD` относительно `BF16`, парный бутстрап `B = 2000`) на **8 языковых моделях** в диапазоне **`1.60–6.23 бит/вес`** (`bpw`).

> **Ревизия `v3.1` (текущая).** Первая версия `v3.0` проигрывала `VTQ v2` по KLD на `4.0–6.0 bpw` и квантовала в `5–10×` дольше. В `v3.1` исправлены три причины (см. §1.1); бинарная раскладка супер-тайла (`816..3184 байт`) не изменилась, изменились порядок обхода треллиса, число подмножеств `nl` и кодовые книги.

## 1. Цели проектирования и ключевые отличия от VTQ v1 и VTQ v2

Главная цель **VTQ v3** — **сократить число инструкций декодирования на вес и убрать узкие места подсистемы памяти** на CPU (`AVX2`, строго `-mno-avx512f`) и GPU (`FP32` и `DP4A INT8` `GEMV`/`GEMM` при `B = 1, 8, 32`), сохранив качество `VTQ v2` и его скорость квантования.

1. **Единый самодостаточный супер-тайл `16 строк × 256 столбцов = 4096 весов` (`816 .. 3184 байт`)**:
   - В `VTQ v2` полоса разбивалась на 5 разнесённых `SoA`-регионов (`codes`, `usgn`, `umid`, `lsb`, `gains`) плюс отдельный тензор экспонент `e[M, K/256]`; чтение 6 несвязанных указателей дробило транзакции HBM/L2.
   - В **VTQ v3** все плоскости битов, индексы усилений и линейные масштабы `uint8 u_sb[16]` упакованы в **одну непрерывную C-структуру `vtq3_st16_*`**, идентичную байт-в-байт для CPU, GPU и файла `.vtq` v3 (`1` линейный поток чтения, до **`1476.9 GB/s = 96.4%`** потолка HBM на `RTX PRO 6000 Blackwell`).
2. **Нулевая стоимость Галуа-логики на GPU (`Joint-1024` LUT в shared memory) и нативный сдвиг `uint16_t` на CPU**: переход к следующему столбцу на CPU — одна инструкция `_mm256_srli_epi16`, на GPU — один сдвиг `s = ((s << 1) | bit) & 0x3FF` без вычисления масок Унгербёка.
3. **Полные `nl = 16` подмножества Унгербёка на всех 20 форматах основного меню** (`1.5 .. 6.0 bpw`) с аддитивными книгами `AT2 (16B+16B)` для `K = 4` и `AT2Z (32B+32B)` с обнулением бита 7 без `vpblendvb` для `K = 5, 6`. Быстрые CPU-режимы `VTQ3_300_FAST` (`nl = 8`) и `VTQ3_500_FAST` (`nl = 4`) оставлены как опция.
4. **Линейный 8-битный масштаб суперблока `uint8 u_sb[16]` (`× 1/128`)** вместо логарифмической экспоненты `2^(0.25·e)`: шаг `0.45%` вместо `18.9%`, без `exp2f` в декодере.
5. **Внутриподблочный tail-biting треллис `16 × 16`**: каждая подгруппа `g` (столбцы `16g .. 16g+15`) всех 16 строк супер-тайла образует один замкнутый треллис из `256` шагов, что позволяет использовать быстрый каузальный энкодер `Block16-LDLQ` из `VTQ v2`.

### 1.1. Что исправлено в `v3.1` относительно `v3.0`

| Проблема `v3.0` | Следствие | Исправление в `v3.1` |
| :--- | :--- | :--- |
| Горизонтальный треллис `1 × 256` по строке + перезапись диагонали `d_row` в `98.6%` строк | `-0.046 бит` SNR, квантование в `6–12×` дольше `v2` | Треллис `16 × 16` внутри подгруппы; энкодер `tcq_ldlq_block256` (тот же, что у `v2`); удалено `8 × __shfl_sync + 4 × __byte_perm` на супер-тайл в `B = 1` |
| `nl = 8 / 4` на `K = 3.5 .. 6.0` | `-0.017 .. -0.077 бит` SNR (голодание кодовой книги) | `nl = 16` на всех 20 форматах через `AT2` / `AT2Z` |
| Кодовые книги обучались с нуля, без перестановки косетов Унгербёка | `-0.005 .. -0.015 бит` SNR | Тёплый старт из `results/vtq_v2_tables.json` + совместная оптимизация `(tab, gain_u8)` Ллойдом–Максом по треллису |

Проверка на слое 12 `Qwen3-8B` (`q/o/gate/down_proj`, `VTQ200 .. VTQ500`): `VTQ v3.1` выше `VTQ v2` по SNR на **24 из 24** точек (`+0.004 .. +0.008 бит`) при той же скорости энкодера.

## 2. Математическая модель реконструкции матрицы

Пусть линейный слой задан матрицей $W \in \mathbb{R}^{M \times K}$, где $16 \mid M$ и $256 \mid K$:

$$
\widehat{W}_{m, :} = \Bigl(\mathcal{R}_K^\top \bigl(\widetilde{W}_{m, :}\bigr)\Bigr) \odot \text{suh}, \qquad
\widetilde{W}_{m, 256 b + t} = d_{\text{row}}[m] \cdot \frac{u_{\text{sb}}[m, b]}{128} \cdot \frac{\text{gain}_{g[m, b, \lfloor t/16 \rfloor]}}{64} \cdot \frac{Q(\text{lab}_{m,b,t},\, u_{m,b,t})}{64},
$$

где:
- $b$ — индекс `256`-столбцового суперблока; $t \in \{0, \dots, 255\}$ — естественный индекс столбца (`0` перестановок);
- $d_{\text{row}} \in \mathbb{F}_{16}^M$ — построчный масштаб (`fp16`), выбирается так, что максимальный по строке `u_sb` попадает около `224`;
- $u_{\text{sb}} \in \{1, \dots, 255\}$ — линейный множитель суперблока, хранится в хвосте супер-тайла (`16` байт на `4096` весов);
- $\text{gain} \in \{1, \dots, 255\}^{2^h}$ — банк усилений подгруппы из `16` весов ($h \in \{1, 2, 3\}$);
- $Q(\text{lab}, u) \in [-127, +127]$ — уровень кодовой книги (`qmax = 127`, `TA + TB ≤ 127` для аддитивных книг);
- $\text{suh} \in \mathbb{F}_{16}^K$ и $\mathcal{R}_K = (H_{b_1} \otimes H_{b_2}) \otimes_{\text{outer}} \operatorname{DCT\text{-}II}_q$ (`rot_block = -1`) либо поблочный `FWHT-256` (`rot_block = 256`).

## 3. Архитектура `16 × 256` супер-тайла и треллиса (`ν = 10`, `1024` состояния)

### 3.1. Внутриподблочный tail-biting треллис

Кодовые биты хранятся как `uint8_t c[16][16][2]`; слово `w = *(uint16_t*)c[g][r]` содержит биты столбцов `16g .. 16g+15` строки `r` (младший байт — столбцы `0..7`, старший — `8..15`).

В `v3.1` треллис подгруппы `g` проходит **все 16 строк подряд** (`256` шагов: `(r=0, j=0..15), (r=1, j=0..15), …, (r=15, j=0..15)`) и замыкается сам на себя: начальное 9-битное состояние строки `0` берётся из старших бит слова строки `15` той же подгруппы. Таким образом, 16 подгрупп супер-тайла — это 16 независимых треллисов, а шаг между строками не требует обмена данными между потоками GPU.

На каждом шаге формируется 10-битное окно $s = (h \ll 1) \mid c_j$, а метка подмножества задаётся масками над $\mathrm{GF}(2)$:

$$
\begin{aligned}
\text{nl} = 16 &: \quad \text{lab}(s) = (s \mathbin{\&} 1) \;\Big|\; \bigl(\pi_{10}(s \mathbin{\&} \text{0x2CE}) \ll 1\bigr) \;\Big|\; \bigl(\pi_{10}(s \mathbin{\&} \text{0x050}) \ll 2\bigr) \;\Big|\; \bigl(\pi_{10}(s \mathbin{\&} \text{0x3B6}) \ll 3\bigr), \\
\text{nl} = 8  &: \quad \text{lab}(s) = (s \mathbin{\&} 1) \;\Big|\; \bigl(\pi_{10}(s \mathbin{\&} \text{0x2CE}) \ll 1\bigr) \;\Big|\; \bigl(\pi_{10}(s \mathbin{\&} \text{0x39C}) \ll 2\bigr), \\
\text{nl} = 4  &: \quad \text{lab}(s) = (s \mathbin{\&} 1) \;\Big|\; \bigl(\pi_{10}(s \mathbin{\&} \text{0x2CE}) \ll 1\bigr),
\end{aligned}
$$

где $\pi_{10}(x)$ — чётность 10-битного слова (генераторы Унгербёка `[359, 40, 475]`, `[359, 462]`, `[359]`).

### 3.2. Раскладка супер-тайла (`pack_supertiles_vtq3`)

| Поле | Размер (байт) | Назначение |
| :--- | :---: | :--- |
| `c[16][16][2]` | `512 B` | Кодовые биты треллиса |
| `usgn[16][16][2]` | `512 B` (`0 B` для `fmt=15,17`) | Знаковые полуоси для $K_{\text{eff}} \ge 2.0$ |
| `u_amp` | `0 .. 2048 B` | Амплитудные биты: `Gosset[8,4,4]` (`256 B`), `D4[4,3,2]` (`384 B`), `D4_eq` (`128 B`), `1b` / `2b` / `4b` (`512 / 1024 / 2048 B`) |
| `gains` | `32 / 64 / 96 B` | $h$-битные индексы усиления на каждую подгруппу `16` весов |
| `u_sb[16]` | `16 B` | Линейный `uint8` масштаб суперблока для каждой строки (`× 1/128`) |

### 3.3. Кодовые книги (`hw_codebook`, `qmax = 127`, `tab / 64`)

| Тип | Форматы | Декодирование на CPU AVX2 |
| :--- | :--- | :--- |

| `u8` | `K = 2.0 .. 3.0` (`16B` / `32B`), `_FAST` | `1–2× vpshufb` + знак |

## 4. Скорость декодирования

### 4.1. Бюджет инструкций горячего цикла (на `32` веса)

| Операция | `VTQ v1` (`LTQ`) | `VTQ v2` (`16×16 SoA`) | **`VTQ v3` (`16×256 Super-Tile`)** |
| :--- | :---: | :---: | :---: |
| Потоков памяти на тайл | `3–4` | `6` (`5 SoA + e`) | **`1` непрерывная структура** |
| Шаг состояния и метки `lab` (GPU) | `popc` / `shfl` + маски (`~9` ALU) | `__popc × 3` + сдвиги (`~11` ALU) | **`1` сдвиг + `1× LDS s_joint`** |

## 6. Бинарный контейнер `.vtq` v3 (`Vtq3Writer` / `Vtq3File`)

Заголовок совместим с `mmap` (`MAGIC = b"VTQ\0"`, `VERSION = uint32_le(3)`), начало секции данных и каждый тензор выровнены на `64` байта. Поскольку `u_sb[16]` встроен в супер-тайл, на матрицу `<prefix>` пишутся **4** тензора:

1. `<prefix>.vtq3.data` — `u8 [N_bytes]`: конкатенация 64-байтно выровненных массивов супер-тайлов;
2. `<prefix>.vtq3.slices` — `i32 [S, 5]`: `[r0, r1, fmt_idx, byte_offset, rot_block]` по полосам смешанной точности;
3. `<prefix>.vtq3.d_row` — `f16 [M]`;
4. `<prefix>.vtq3.suh` — `f16 [K]`.

**Сквозная проверка**: все `196` матриц `Llama-3.2-3B-Instruct @ 3.0000 bpw` записаны в файл `1,065,657,856` байт и загружены обратно через `Vtq3File` — **`0.000000` дрейфа KLD** (`0.04084153 / 0.05497863` в памяти и после чтения с диска). Отдельно все 22 обученных формата проходят `Vtq3Writer → Vtq3File` с `max_diff = 0.0e+00`.

## 7. Энкодер `VTQ v3.1`

1. **`Block16-LDLQ` по внутриподблочным треллисам** (`ldlq_block256_cuda` из [`src/cuda/tcq_viterbi.cu`](../../src/cuda/tcq_viterbi.cu), то же ядро, что у `VTQ v2`): 16 стадий каузальной обратной связи Холецкого внутри `256`-столбцового блока, двухпроходный tail-biting Витерби (`1024` состояния, радикс-4, `__ballot_sync`), совместный выбор `(gain, состояние)` с `n_cand = 4` при `2^h > 4`.
2. **Масштабы**: `d_row` заранее центрируется так, что максимальный по строке `u_sb ≈ 224` (`0` насыщений на `255` на слоях `Qwen3-8B`), затем `u_sb` уточняется монотонно по Холецки-взвешенной ошибке (принимается, только если ошибка уменьшилась).
3. **Глобальный рефит**: чередующиеся проходы `(c_row → fp16 d_row, fp16 suh)` в замкнутой форме по полному гессиану. По умолчанию **1 проход** (`VTQ3_REFIT_SWEEPS=1`): второй проход даёт тот же SNR (разница `≤ 0.001` бит на 12 реальных матрицах `Llama-3.2-3B`), но стоит `+20%` времени на широких `K` (см. §7.2). Модельные прогоны §8 выполнены ещё с `VTQ3_REFIT_SWEEPS=2`.
4. **`VTQ3_GS_SWEEPS`** (по умолчанию `0`): `1` — один параллельный проход Гаусса–Зейделя с остаточным Витерби (`+0.006 бит` SNR на слое, но `+40–90%` времени и без выигрыша в KLD на `Llama-3.2-1B`), `2` — полный повторный `LDLQ`.
5. **`quantize_rings_vtq3`** (эмбеддинги, `lm_head`, PLE `Gemma 4`): прямой 1D tail-biting Витерби по кольцу длины `128 / 160 / 256` без дополнения нулями.
6. **`polish_model_scales_kld_checkpointed`**: сквозной полиш `(d_row, suh)` по финальной KL-дивергенции с чекпоинтингом слоёв (`0` дополнительных бит).
7. **Обучение кодовых книг** (`python -m src.vtq_v3 --train-tables`, `~2 мин` на `RTX 5070 Ti`): тёплый старт из `VTQ v2`, `10` итераций совместного Ллойда–Макса `(tab, gain_u8)` по треллису, координатный поиск `gain_u8 ± 1, 2` и калибровка `distortion_ratio` на `Llama-3.2-3B-Instruct`.

## 9. Итог `v3.1` относительно `VTQ v2`

- **Скорость декода**: GPU `B = 1` — **`+20% .. +105%`** на `RTX PRO 6000` и **`+37% .. +72%`** на `RTX 5070 Ti`; CPU AVX2 — **`+2% .. +36%`** на всех битностях.
- **Качество**: против `EXL3` — выигрыш во всех парах по `nem` (`p ≥ 0.9995`), по `mul` две статистические ничьи (`Qwen3-8B @ 3.0`, `Qwen3.8-27B @ 3.0043`); против `VTQ v2` — паритет в пределах `±3%` на большинстве точек, заметные выигрыши на `Gemma-4` (`3.5–4.0 bpw`, до `-14.7%`), `Llama-3.1-8B` (`3.44 bpw`, `-7.6%`), `Llama-3.2-3B` (`3.44 bpw`, `-4.3%`), `Llama-3.2-1B` (`2.1 bpw`, `-4.9%`); отставание на `Qwen3-8B` (`+2..+7%`, §8.4).
- **Время квантования**: паритет с `VTQ v2` на одном стенде и на `27B / 30B`; в `3–4×` быстрее `EXL3`.
