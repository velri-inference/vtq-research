## Куда имеет смысл направить первый новый тест

**Порядок первого каузального LDLQ-прохода по уже существующим группам.** В просмотренных результатах не найдено отдельного A/B для текущего VTQ: переставить *целые* тайлы по 256 столбцов и/или *целые* группы по 16 внутри тайла по статистике калибровки, применить ту же перестановку к обеим осям Hessian, после кодирования вернуть коды, gain и масштабы на их штатные места. Это не обратный GS-проход после первого кодирования, не перестановка отдельных весов в треллисе и не перестановка выходных каналов SwiGLU. Гипотеза ничего не добавляет в файл и не требует другого декодера. Возможный проигрыш — стоимость переиндексации при создании. Проверять сначала точное декодирование из байтов и KLD, затем перенос с GPT-2 на другую архитектуру, время и пик памяти. Отсутствие записи в архиве не доказывает, что вне него варианта не запускали.

### После аудита: результат первого прогона (exp09)

На [отборочной трети WikiText-2, GPT-2](../../results/exp09_gpt2_discovery.json) выиграл порядок `act-desc` (дисперсии после вращения, по убыванию сначала тайлы, затем группы внутри тайла). Его зафиксировали **до** проверки на последней трети текста, с новыми seed `3000/4000`. Парное среднее изменение KLD, минус = лучше:

| | `VTQ_200` | `VTQ_300` | `VTQ_400` |
| --- | ---: | ---: | ---: |
| [GPT-2](../../results/exp09_gpt2_confirm.json) | **−2.68%** | +1.03% | −0.84% |
| [Qwen3-0.6B](../../results/exp09_qwen_confirm.json) | **−2.30%** | +0.83% | −2.02% |

Только у `VTQ_200` парный 95%-интервал не пересёк ноль на обеих моделях. Бутстрап по 64 контекстам, усреднение двух seed внутри контекста, а не удвоение числа наблюдений. Кодек и число бит без изменений, все 24 контрольных/опытных прогона подтверждения проверяли восстановленные веса из `.vtq` побитово. Прототип переиндексации дороже: на прогретом 2-битном Qwen для seed `4000` время 4.084 → 4.154 с и дополнительная VRAM 161 → 240 МиБ. Не делать дефолтом.
