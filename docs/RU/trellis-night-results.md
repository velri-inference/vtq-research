# Ночные проверки VTQ: журнал решений (Colab G4)

Контроль — действующий VTQ, не исторический LIQK. На WikiText-2 первая треть используется для калибровки, средняя для выбора, последняя для независимой проверки. При подтверждении меняются seed; парный bootstrap по контекстам не подменяется подсчётом seed как независимых текстов. Сохранённые байты декодируются до сравнения с BF16. Проценты относятся к KLD, а не к «процентам качества».

| Опыт | Результат и решение |
|---|---|
| exp09: порядок первого LDLQ-прохода | `act-desc` на 3-битном GPT-2 дал −3.10% **при отборе**, но не подтвердился на 3 битах. На 2 битах: −2.68% GPT-2, −2.30% Qwen3-0.6B на подтверждении. [Подробности и источники](experiment-inventory.md). |
| exp11: экономная реализация + полный перенос | Тайл-гатер без индексных сеток и слитый refit снизили пиковую VRAM прототипа, но из-за порядка FP32-редукций не все результаты битово равны исходному `act-desc` ([хэши/время/память](../../results/exp11_cost.json)). [Llama-3.2-1B-Instruct](../../results/exp11_llama1b_transfer.json): 112 матриц, ровно 2.10533 bpw линейных весов, одинаковые Fisher/GPTAQ, 3 seed. ΔKLD −0.14% nem и −0.18% mul; **оба ДИ содержат ноль**. Прогретое время создания без проверочного I/O ~20.24 против ~20.28 с, измеренный пик с проверкой одинаков. Не включать как универсальный пресет. |
| exp10: TSB1, четыре формы на gain-заголовок | Независимые LUT вместо четырёх растяжек. На GPT-2 не обогнали контроль с одной исходной таблицей и изменённым стартовым масштабом. [TSB1](tsb1-experiment.md). |
| exp12: P2T1, radix-4 над двумерными векторами | Два кодовых бита + 4-битный индекс 2-D вектора на **пару**, 2 бита усиления на 8 пар. При 2048 состояниях декартова таблица включает кодовые последовательности исходного скалярного треллиса; полная 2-D LUT — 8192 байта. [RD и проверка по независимому Bellman-оракулу](../../results/exp12_pair_trellis.json). [Отбор GPT-2](../../results/exp12_gpt2_discovery.json): лучший `pair-base-H` использовал именно декартову таблицу и парную метрику, −3.11%, но ~5.36 с вместо ~1.20 с. На подтверждении **+0.92%** [GPT-2](../../results/exp12_gpt2_confirm.json), **+2.27%** [Qwen](../../results/exp12_qwen_confirm.json); оба ДИ пересекают ноль. Не инвестировать в оптимизацию ядра на основании этого результата. |
| exp13: LRT1, низкоранговая коррекция ошибки | 1 вместо 2 бит на индекс усиления каждой группы из 16; сэкономленные байты покупают `A_i8[M,r], B_i8[r,K], scale_f32[r]`. Даже с заголовком каждая отдельная матрица укладывается в старые **тайлы и масштабы без заголовка**. На GPT-2 r=2/4. Отнятый бит ухудшил KLD на 5.03%; Hessian-взвешенная коррекция после квантования сократила проигрыш до 3.08%, но не закрыла его. [Результат](../../results/exp13_gpt2_discover.json). Это измерение кодирования, не скорости matvec с боковой ветвью. |

- **exp13-pre** — те же байты, но сначала выделить подпространство исходных весов, а не ошибки. На GPT-2 лучший такой режим (`pre-hessian`) всё равно хуже обычного VTQ на 2.48%; подтверждение не запускалось ([данные](../../results/exp13pre_gpt2_discover.json)).
- **exp14, базис V/O:** преобразовать `W_v` в `T W_v`, а соответствующие столбцы `W_o` для каждой группы голов — в `W_o T^{-1}`. Это не добавляет операции после квантования. [На отборе](../../results/exp14_qwen_discovery.json) победил обычный знаковый Hadamard (−2.54%), не PCA и не балансировка. На подтверждении для 2/3/4 бит: [Qwen](../../results/exp14_qwen_confirm.json) +1.12/+1.77/−0.75%, [Llama-1B](../../results/exp14_llama1_confirm.json) +0.05/−0.45/−0.85%; все шесть ДИ содержат ноль. Не включать по умолчанию.

- **exp15, WRC1 (3 бита).** Два младших бита блочного масштаба отданы коэффициенту поправки вдоль направления Уолша, без роста тайла (1616 байт). `walsh-fit-zero` выиграл [отбор](../../results/exp15_gpt2_discover.json) всего на 0.20%. На независимых данных [GPT-2](../../results/exp15_gpt2_confirm.json) −0.14% KLD (ДИ включает ноль), [Qwen](../../results/exp15_qwen_confirm.json) +0.40% (ДИ выше нуля), тёплое кодирование Qwen 5.48→5.96 с. Вариант закрыт.
- **exp16, начальный масштаб.** Однопроходный предиктор обучен выбирать масштаб по реальной ошибке Витерби; [синтетическая MSE](../../results/exp16_scale_teacher.json) и [модельный KLD](../../results/exp16_gpt2_discovery.json) не взаимозаменяемы. Для 2 бит уже на отборе победил штатный RMS. Для 3/4 бит до независимой проверки зафиксирован `adaptive`: [GPT‑2](../../results/exp16_gpt2_confirm.json) +1.05/+0.69% KLD, [Qwen](../../results/exp16_qwen_confirm.json) +1.99/+0.67%. Все четыре парных 95% ДИ включают ноль. Улучшение не подтвердилось, предиктор не включать.
- **exp17, структурная компенсация GPTAQ.** [Отбор на 32 отдельных последовательностях Llama-1B](../../results/exp17_1b_cal_discovery.json), `VTQ_300`, 2 seed, 112 матриц. В `down_proj` полная регрессия с диагональным априорным значением (`prior-down`) дала −2.36% KLD; прогретая пара: 22.08 с в обоих случаях, одинаковый пик 4.95 GB. Напротив, замена полной карты на диагональную (`diag-down`) экономит время/память, но повышает KLD на 2.51%. Независимая проверка (три новых seed): [1B](../../results/exp17_1b_confirm.json) Nemotron +3.53% KLD (95% ДИ выше нуля), multilingual +0.60% (ДИ включает ноль); [3B](../../results/exp17_3b_confirm.json) −0.06% и −1.29%, оба ДИ включают ноль. Универсального выигрыша нет, штатный GPTAQ не заменять.

- **exp18, конечный RMSNorm.** Коды всех матриц одинаковы в сравниваемых вариантах: меняются только значения уже существующего BF16-вектора нормы. По двум потокам GPTAQ оцениваются поканальные коэффициенты и/или скалярная температура. [Отбор Llama-1B](../../results/exp18_llama1_discovery.json): `feature-temperature` для 2/3 бит (−0.330%/−0.058% KLD), `temperature` для 4 бит (−0.043%). Только при 2 битах парный 95% ДИ не содержит ноль; на обоих seed немного лучше также PPL и совпадение top‑1 с учителем. Цена подгонки ~12 мс; это не ускорение инференса. [Подтверждение на трёх новых seed, 2/3 бита](../../results/exp18_llama1_features_confirm.json): на Nemotron KLD −0.498%/−0.141% (оба парных 95% ДИ ниже нуля), на multilingual −0.015%/+0.021% (оба ДИ включают ноль). Для 2 бит средняя PPL на Nemotron 7.462→7.427, на multilingual 8.126→8.148. На [4 битах](../../results/exp18_llama1_scalar_confirm.json) KLD +0.005%/−0.020%, оба ДИ включают ноль. Не применять как универсальную настройку.

- **exp19, компенсация остаточного выхода слоя через `down_proj`.** При оценке поправки GPTAQ решаем систему в пространстве выходов MLP, прибавляя к ошибке ветви MLP также ошибку входящего остаточного потока. На [отборе](../../results/exp19_1b_discover.json) выбран `skip-full`; коэффициент больше не менялся. На [независимой Llama‑3.2‑1B](../../results/exp19_1b_confirm.json), `VTQ_300`, 3 seed, KLD −5.57% на Nemotron и −5.90% на multilingual (оба парных 95% ДИ ниже нуля). Контроль `output-only`, который отличается только отсутствием этой поправки: +1.90%/−0.49% к штатному GPTAQ. Прогретое кодирование без проверочного I/O 22.08→18.28–18.29 с, дополнительный пик VRAM с roundtrip 4.954→3.935 GB, 3.16783 bpw для тех же 112 матриц (с учётом тайлов и шкал, не bpw всей модели). Формат, размер и операции декодера неизменны. На [Llama‑3.2‑3B](../../results/exp19_3b_confirm.json) при `VTQ_300` перенос подтвердился: −8.81%/−7.40% KLD (оба парных ДИ ниже нуля), 196 матриц, три seed. На offset 4000 квантование 56.32→50.22 с, дополнительный пик 5.84→5.34 GB. На Llama‑1B та же замороженная поправка проверена и на [VTQ_200](../../results/exp19_1b_VTQ_200_confirm.json) (−5.69%/−3.70% KLD) и на [VTQ_400](../../results/exp19_1b_VTQ_400_confirm.json) (−5.03%/−5.67%). Во всех четырёх случаях верхняя граница парного 95% ДИ ниже нуля. На offset 4000 время 20.28→16.46 с и 22.92→19.12 с соответственно, дополнительный пик в обеих парах 4.954→3.935 GB. Это проверки переноса по размеру и битности внутри Llama, не по архитектуре.
- **exp20, экономия без изменения байтов.** [Llama‑3.2‑1B, `VTQ_300`, G4](../../results/exp20_llama1_exact.json): для каждого из трёх seed все 112 матричных файлов, включая их заголовки, совпали по SHA‑256 со штатным кодером. Прогретые прогоны (offset 3000/4000): время квантования без проверочной записи/чтения 22.07–22.08 → 21.06 с (−4.6%); дополнительный пик VRAM, включая проверку roundtrip, 4.954 → 3.914 GB (−21.0%). Раздельно повторное использование результата MLP учителя даёт 21.39–21.40 с, одноразовый аккумулятор ковариации — 21.73–21.74 с. Файл и декодер прежние. Комбинация доступна через `quantize_llama_model_vtq(..., compact_gptaq=True)`; [Интегрированный путь на Llama‑3.2‑3B](../../results/exp20_llama3_exact.json) также совпал побайтно (196 матриц × 3 seed). Прогретое время 56.37–56.39 → 53.94–53.95 с (−4.3%), дополнительный пик 5.840 → 4.816 GB (−17.5%). Это проверка кодера на двух Llama, не проверка гибридов или ускорение декодирования; режим остаётся явным.

- **exp21, протокол проверки на гибридах.** `src/exp21_hybrid_skip.py`: Qwen3.5‑4B (DeltaNet/full) и Gemma 4 E4B-it (sliding/full, PLE, общий KV). Первый прогон фиксирует `VTQ_300`, seed offset 2000, 16×512 калибровочных токенов соответствующего токенизатора. Штатный HF text forward, собственные Fisher и полные токенизированные трассы; сравнить `natural` без GPTAQ, `output-only` и буквальный `skip-full` только на down_proj. Для Gemma отдельно помечен `skip-tangent`: перенос поправки сквозь выходной RMSNorm MLP; не смешивать с буквальным переносом. [Qwen3.5‑4B, первый seed](../../results/exp21_qwen35_2000.json): `skip-full` −1.80% KLD на Nemotron и −0.78% на multilingual, оба парных ДИ включают ноль; `output-only` +1.54%/+1.84%. Размер одинаков: 200 матриц по 3.1648 bpw с учётом шкал. Кодирование с учётом прохода учителя 27.49→30.26 с: для этого гибрида условие отсутствия регрессии пока не выполнено. Время — один прогон, не устойчивый бенчмарк. На дополнительных seed [3000](../../results/exp21_qwen35_3000.json) и [4000](../../results/exp21_qwen35_4000.json) знак эффекта Qwen меняется; на multilingual в обоих случаях KLD немного выше базы. [Gemma 4 E4B, seed 2000](../../results/exp21_gemma4_2000.json): после исправления загрузки (SDPA для текста, eager для неиспользуемых модальностей) все 342 матрицы прочитаны обратно при 3.16605 bpw. Буквальный `skip-full` резко ухудшил абсолютный KLD: 0.07806→5.63772 и 0.09294→11.90735; не применять. Заранее выделенный `skip-tangent`, учитывающий post-MLP RMSNorm, дал −2.86%/−2.65%, но оба ДИ содержат ноль, кодирование 33.67→37.55 с. Итог по трём seed (усреднение внутри диалога, 4000 парных bootstrap-выборок): [Qwen3.5, `skip-full`](../../results/exp21_qwen35_pool.json) −0.57%/+0.18%, [Gemma 4, `skip-tangent`](../../results/exp21_gemma4_pool.json) −0.64%/−0.12%; все четыре 95% ДИ включают ноль. Выигрыш с Llama не перенёсся. Для обеих гибридных моделей оставить исходный VTQ.

- **exp22, чувствительность отдельных токенов к post-MLP RMSNorm (Gemma 4).** Вместо GPTAQ взвесить входы для гессиана `down_proj` обратным средним квадратом выхода MLP, без прохода учителя. [Три новых seed](../../results/exp22_gemma4_pool.json), `VTQ_300`: −0.65%/−2.82% KLD (Nemotron/multilingual); перемешанный контроль −0.68%/−0.97%; все парные ДИ относительно штатного VTQ включают ноль. Прогретый дополнительный пик студента с roundtrip выше на 0.34 GB (3.16 вместо 2.82 GB). Не включать.

- **exp23, один калибровочный проход на гибридах.** Для одной партии 16×512 `single-forward` кодирует каждую линейную проекцию перед её первым вызовом без повторов начала блока. На двух offset с обратным порядком A/B все файлы совпали по SHA‑256: по 200 матриц Qwen3.5‑4B ([8000](../../results/exp23_qwen35_8000.json), [9000](../../results/exp23_qwen35_9000.json)) и по 342 матрицы Gemma 4 ([8000](../../results/exp23_gemma4_8000.json), [9000](../../results/exp23_gemma4_9000.json)). Сравнение вторых (прогретых) запусков разных offset: Qwen 27.27→25.73 с, дополнительный пик 2.538→2.125 GB; Gemma 33.65→31.83 с, но пик 2.610→2.694 GB. Знак разницы памяти такой же при сравнении двух первых запусков. На Qwen критерий без регрессии пройден, на Gemma пока нет. Нельзя подменять один полный батч первым из нескольких батчей или переносить эти цифры на инференс.

- **exp24, попытка убрать рост пика Gemma в exp23.** Вращение широкого гессиана полосами и перезапись правой части треугольной системы сохранили байты всех файлов. При сравнении вторых запусков в противоположных порядках A/B: [Gemma, кандидат](../../results/exp24_gemma4_10000.json) 32.13 с / 2.694 GB против [базы](../../results/exp24_gemma4_11000.json) 33.50 с / 2.610 GB; [Qwen, кандидат](../../results/exp24_qwen35_10000.json) 25.59 с / 2.125 GB против [базы](../../results/exp24_qwen35_11000.json) 27.38 с / 2.538 GB. На Gemma пик кандидата по-прежнему на 84 MB выше, в том числе при сравнении первых запусков: ограничение этого временного буфера не снизило пик всего кодирования. Общий критерий **не пройден**, режим не продвигать.

Ни один проигравший вариант не меняет формат файлов или параметры по умолчанию. Отдельно найден и исправлен баг `VtqFile`: стартовые `0x20` в *данных* могли быть приняты за заполнение заголовка. Регрессия — `src/test_vtq_payload_offset.py`.
