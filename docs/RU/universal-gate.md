# Общий критерий и бюджет: продолжение на Colab G4

Граница времени: пять часов с момента продления пользователем. Рабочая сессия `trellis-night`, метка конца — `/content/trellis-night/universal_deadline`. Запускать расчёты только на G4, заранее выгружать частичные результаты. Не продолжать после границы и не считать запущенную задачу завершённой.

## Практический итог

| Что включать | Решение по восьми моделям, `VTQ_300` |
|---|---|
| `VtqFile(path, codec=codec)` — только загрузчик | **Прошёл:** материализация матриц на GPU в 6.2–8.3× быстрее при одинаковых FP32-битах и пике VRAM; у крупнейших матриц ниже дополнительный CPU RSS. Квантователь и файл можно вообще не менять. [Инструкция](vtq-native-io.md). |
| Нативная запись без изменения копирования исходных тензоров | Быстрее и побайтно эквивалентна на 8/8, но небольшой рост пикового CPU RSS полного экспорта на части моделей. **Не включать по строгому критерию.** |
| Параллельное копирование неизменённых тензоров | Пик RAM ниже на 8/8, время лучше на 7/8, но нет ускорения на MoE‑30B. **Не включать по строгому критерию.** |
| Изменения ради качества | Единого выигрыша KLD нет. Существенный результат для Llama от коррекции остаточного выхода не перенёсся на гибриды. [Исследовательский журнал](trellis-night-results.md). |

## Что значит «на всех»

Штатная восьмёрка из §8 `vtq-format.md`: Llama‑3.2‑1B, Llama‑3.2‑3B, Llama‑3.1‑8B, Qwen3‑8B, Qwen3.5‑4B, Gemma 4 E4B-it, Qwen3.8‑27B и Qwen3‑30B‑A3B-Instruct-2507. Дополнительные контрольные модели этой серии: GPT‑2 и Qwen3‑0.6B. Не менять набор после появления результата. Не заменять 27B или MoE меньшей плотной моделью. Различать текстовую часть Gemma, выделенное квантование PLE и MoE-экспертов.

- Универсальный результат требует заранее названного улучшения **для каждой** модели, без регрессии других осей, при одинаковом числе байтов. Среднее, условное включение только на победителях, «не хуже в среднем», отсутствие значимости и отсутствие измерения — не прохождение критерия.
- Для нового кодера без изменения формата сильнейшее доказательство качества — идентичность реальных выходных файлов (все коды, шкалы, метаданные); декодер не меняется. Синтетический тест всех форматов необходим для сериализатора, но недостаточен вместо модельных измерений. Побайтовая проверка каждого компонента явно отличается от хеша всего пакета.
- Для кандидата качества: BF16 teacher-forced KLD на обеих трассах с парными интервалами; размер с накладными данными, время и пиковая VRAM при том же протоколе кодирования. Для производительности: одинаковая нагрузка, прогрев и смена порядка, не считать выигрыш отдельной фазы ускорением всей квантизации. Отмечать CPU RAM и дополнительные расходы на сборку/инициализацию.
- Итог по каждому варианту: `прошёл на всей сетке`, `не прошёл` (назвать модель/метрику) или `не доказан` (назвать непроверенные случаи). Срок важнее попытки выдать неполное покрытие за полное.

Промежуточный результат exp25: на [Qwen3‑30B‑A3B](../../results/exp25_moe30_writer.json) все 12 480 файлов матриц (12 288 экспертных, 192 проекции attention) совпали по SHA‑256, их содержимое после чтения совпало с результатом энкодера. Суммарное время записей 37.38→18.01 с при одной общей квантизации; 822 с в журнале включают обе записи, SHA и контрольное декодирование и не являются отдельным временем базового или нового кодера. На дополнительных контролях при `VTQ_200/300/400` совпали 144/144 файла [GPT‑2](../../results/exp25_gpt2_writer.json) и 588/588 файлов [Qwen3‑0.6B](../../results/exp25_qwen_writer.json). Суммарная запись по трём битностям: 0.420→0.177 с и 2.266→0.893 с соответственно; выигрыш есть отдельно в каждом из шести сравнений. Это две дополнительные модели, не замена какой-либо из штатной восьмёрки. Остальные модели и память оцениваются отдельно.

**exp28 завершён на 8/8**: 16 пар A/B или B/A, 32 независимые сборки. SHA целой модели совпал в каждой паре. Даже худшее из двух времён нового writer меньше лучшего из двух времён штатного на каждой модели (от 25.35 против 26.21 с на 1B до 218.90 против 250.20 с на 27B). Это вывод по времени и байтам, не по RSS. [Llama‑8B A/B](../../results/exp28_llama8_1.json) и [B/A](../../results/exp28_llama8_2.json) также сохранены.

Протокол exp28: один файл с фактическими нетронутыми исходными тензорами, независимый процесс на сборку, одинаковая калибровка, квантование + запись + fsync; SHA всего файла, CPU RSS и VRAM. Для Gemma PLE остаётся в исходном типе в обеих сборках. Не выдавать exp25 за выполнение этого теста. [Gemma A/B](../../results/exp28_gemma4_1.json), [B/A](../../results/exp28_gemma4_2.json): целый файл 9 680 004 160 байт неизменен; до `fsync` 66.72→61.52 и 65.25→62.43 с. При этом дополнительный RSS увеличился в обоих порядках примерно на 22 MB: один только нативный упаковщик не прошёл строгий критерий для полного экспорта. На [Qwen‑8B A/B](../../results/exp28_qwen8_1.json), [B/A](../../results/exp28_qwen8_2.json) файл тоже одинаковый, 115.93→105.50 и 116.67→107.19 с; разница RSS здесь меняет знак. Восстановленные [Llama‑3B A/B](../../results/exp28_llama3_1.json) и [B/A](../../results/exp28_llama3_2.json) подтверждают тот же компромисс: 66.05→60.32 и 64.59→60.75 с, но дополнительный RSS выше примерно на 19–20 MB; полные SHA совпадают. На [Qwen3.5 B/A](../../results/exp28_qwen35_2.json) аналогично, 42.30→38.09 с и +14 MB. Это основание проверить потоковое копирование неизменённых тензоров отдельно, а не пренебрегать регрессией Gemma.

Exp26, чтение матричных файлов в FP32 на GPU (не скорость инференса): [30B‑MoE](../../results/exp26_moe30_materialize.json) 403.99→65.19 с, SHA результатов совпал для всех 12 480 матриц; [27B](../../results/exp26_qwen27_materialize.json) 432.19→52.01 с, 400/400. Пик дополнительной GPU-памяти отдельного вызова не изменился на обеих моделях. В изолированном процессе для крупнейшей фактической матрицы каждой модели дополнительный пик CPU RSS при распаковке 308.6→33.6 MB и 3168.8→356.6 MB соответственно. Сетка exp26 завершена: при `VTQ_300` материализация матричных файлов в FP32 на GPU ускорилась на **каждой** из восьми основных моделей (6.20–8.31×). Все 14 206 SHA‑256 итоговых FP32-матриц совпали, измеренный дополнительный GPU-пик отдельного вызова не вырос ни на одной модели. Подробности: [1B](../../results/exp26_llama1_materialize.json) 15.23→2.09 с; [3B](../../results/exp26_llama3_materialize.json) 45.47→6.03; [Llama‑8B](../../results/exp26_llama8_materialize.json) 123.90→15.01; [Qwen‑8B](../../results/exp26_qwen8_materialize.json) 122.44→14.93; [Qwen3.5](../../results/exp26_qwen35_materialize.json) 56.26→7.59; [Gemma](../../results/exp26_gemma4_materialize.json) 63.38→8.40. Для крупнейшей фактической матрицы каждой модели дополнительный CPU RSS изолированной распаковки также уменьшился. [GPT‑2](../../results/exp26_gpt2_materialize.json) и [Qwen‑0.6B](../../results/exp26_qwen_materialize.json) прошли дополнительные проверки. Это подтверждение по оси **декодирования при загрузке**; квантизатор может по-прежнему использовать прежний writer, файл и ядро генерации неизменны. Не экстраполировать на токены/с или wall-time старта сервера целиком.

Exp27, качество: [отбор знаков вращения на панели из 24 строк, GPT‑2](../../results/exp27_discovery.json). По фиксированному минимаксному критерию на 2/3/4 битах победил `natural`. `panel-mse` дал +4.38% / −2.12% / −1.13% KLD, `panel-H` +0.27% / −0.10% / −0.26%. На 3 битах фиксированный сдвиг seed сам по себе дал −1.96%, а оба панельных варианта кодировали медленнее. На отборе не получен кандидат для переноса: подтверждения GPT‑2/Qwen не запускали, новые знаки в настройки не включать.

Exp30/31, попытка ускорить и уменьшить RSS полного экспорта: прямое копирование неизменённых весов из safetensors и его перекрытие с кодированием. В [Gemma, exp30](../../results/exp30_gemma4_native.json) дополнительный RSS 8.49→0.40 GB и полный SHA прежний, но 73.20 с против 65.25–66.72 с у базы. В [MoE, exp31](../../results/exp31_moe30_native.json) 1.27 GB вместо ~60 GB при прежнем SHA; 651.10 с хуже даже первого запуска базы 645.10 с, а прогретая база 377.97 с. На этом размере состояние файлового кеша существенно. На [27B](../../results/exp31_qwen27_native.json) и [Qwen3‑8B](../../results/exp31_qwen8_native.json), напротив, одновременно уменьшились время и RSS. exp31 завершён на всех восьми: во всех восьми случаях полный файл совпал с обеими независимыми эталонными сборками, дополнительный пик VRAM не изменился, а дополнительный CPU RSS уменьшился. На 7/8 время до `fsync` ниже лучшего эталонного: [Llama‑1B](../../results/exp31_llama1_native.json) 22.93 против 26.21 с, [3B](../../results/exp31_llama3_native.json) 58.45 против 64.59, [Llama‑8B](../../results/exp31_llama8_native.json) 150.63 против 167.10, Qwen‑8B 97.90 против 115.93, [Qwen3.5](../../results/exp31_qwen35_native.json) 29.42 против 42.30, [Gemma](../../results/exp31_gemma4_native.json) 45.71 против 65.25, 27B 205.42 против 250.20. На MoE есть регрессия времени; один прогон кандидата нельзя объявлять устойчивым A/B по состоянию файлового кеша. Универсального выигрыша полного экспорта этими измерениями не установлено.

Exp29: после подгонки кодов и масштабов приблизить вторые моменты выходов по строкам к BF16 через уже имеющийся `d_row`. До подтверждения выбран показатель `0.5`. На [GPT‑2](../../results/exp29_gpt2.json), `VTQ_200/300/400`: −1.18%/−0.33%/+0.15% KLD. На [Qwen3‑0.6B](../../results/exp29_qwen.json): +0.40%/+0.44%/+0.38%; парные интервалы для 2 и 3 бит целиком выше нуля. Дополнительная трёхseed-проверка на гибридах не дала сохранённого объединённого результата до лимита и не засчитывается. Отдельные выигрыши не компенсируют проигрыш на Qwen3‑0.6B; исходную коррекцию по умолчанию не менять.

`skip-full`, `compact_gptaq`, результаты одиночного полного батча и варианты RMSNorm не являются общим решением по этому критерию. Архитектурные результаты сохраняются отдельно и не переносятся на неохваченные модели.
