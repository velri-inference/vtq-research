# Спецификация формата и квантователя VTQ v2 (`.vtq`, `VERSION = 2`)

Документ описывает бинарный формат квантования весов **VTQ v2** (`MAGIC = b"VTQ\0"`, `VERSION = 2`), эталонный декодер [`src/vtq_v2_format.py`](../../src/vtq_v2_format.py), производительный квантователь [`src/vtq_v2.py`](../../src/vtq_v2.py), высокоскоростные ядра декодирования для CPU AVX2 ([`src/cpu/vtq2_avx2_bench.c`](../../src/cpu/vtq2_avx2_bench.c)) и GPU Blackwell `sm_120` ([`src/cuda/vtq2_matvec_bench.cu`](../../src/cuda/vtq2_matvec_bench.cu)), а также результаты сквозных бенчмарков качества (`KLD` относительно `BF16`, парный бутстрап `B = 2000`) в диапазоне **`1.59–6.22 бит/вес`** (`bpw`).

---

## 1. Цели проектирования и ключевые отличия от VTQ v1 (`LTQ v1` / `TCQPQ`)

Формат **VTQ v2** решает пять фундаментальных ограничений `VTQ v1`, **не увеличивая вычислительную стоимость декодирования (compute)** на CPU (`AVX2`, без `AVX-512`) и GPU (`CUDA GEMV`):

1. **Единая битовая раскладка тайла с вынесенной знаковой плоскостью `usgn[32B]`**:
   - В `VTQ v1` некодированные биты `u` смешивали знак и амплитуду, из-за чего таблицы уровней были знаковыми и на CPU AVX2 упирались в 32-записной предел `vpshufb` (`nl = 8` при `K = 3`, `nl = 4` при `K = 4, 5`).
   - В `VTQ v2` старший некодированный бит вынесен в отдельную 32-байтовую плоскость `usgn` (`1` регистр `YMM` на весь `256`-весовой тайл). Оставшиеся плоскостные массивы амплитуд имеют строго выровненные размеры (`0` при `K = 2`, `1` бит при `K = 3`, `uint16` при `K = 4`, `2+1` при `K = 5`, `uint32` при `K = 6`), что одновременно **ускоряет декод на `+14.7%..+18.9%`** и открывает **`nl = 16` подмножеств Унгербёка на всех битностях `K = 2..6`**.
2. **Антиподальные и зонированные аддитивные `uint8` кодовые книги с защитой `qmax = 128`**:
   - Все `26` форматов хранят в заголовке компактные беззнаковые байтовые массивы (`at`, `at2_16_16`, `at2z_32_32`) с максимумом `qmax = 128` (`257` эффективных знаковых уровней `[-128..+128]`), что математически исключает переполнение `int16` в `vpmaddubsw` (`2 × 128 × 127 = 32512 ≤ 32767`) при любых весах и активациях (`rel_err ≤ 2.1e-7`).
   - Разрыв с теоретическим пределом Шеннона $R(D)$ на $\mathcal{N}(0, 1)$ сжат до **`0.126–0.147` бит** во всём рабочем диапазоне `2.09–5.15 bpw` (против `0.140–0.200` бит в `VTQ v1`).
3. **Дробная решётка Госсета $E_8$ на младшем бите (`gosset84`, код Хэмминга `[8, 4, 4]`, скорость `K - 0.5`)**:
   - Заменяет парное повторение `D2` на всех полуцелых форматах (`1.59, 2.59, 3.65, 4.65, 5.71 bpw`). Каждые 8 последовательных младших битов кодируются 4-битным словом расширенного кода Хэмминга `[8, 4, 4]` (`16` кодовых слов двоичной решётки $E_8$).
   - На CPU AVX2 все 16 кодовых слов раскрываются **одним `vpshufb`** по константе `HAM_CW8[16]`; на GPU — через `sham[16]` в shared memory без банк-конфликтов. Выигрыш качества над `D2` достигает **`+0.146` бит на `1.59 bpw`** и **`-12%..-14%` KLD на `2.59 bpw`** при одновременном ускорении AVX2-декода.
4. **Каноническое факторизованное кронекеровское вращение $\mathcal{R}_K = H_{2^a} \otimes \operatorname{DCT\text{-}II}_q$ по всей ширине матрицы `K`**:
   - Вместо изолированных блоков Адамара по `256` элементов (`FWHT-256`) применяется ортогональное преобразование по полной входной размерности $K = 2^a \cdot q$ ($256 \mid K$, $q$ нечётно: $q=1$ для `4096/8192`, $q=3$ для `768/1536/3072/6144/12288`, $q=5$ для `2560/5120`, $q=7$ для `3584/7168/14336`).
   - Факторизация $\mathcal{R}_K = H_{b_1} \otimes (H_{b_2} \otimes \operatorname{DCT\text{-}II}_q)$ выполняется двумя малыми IEEE-FP32 матричными умножениями (`7.25×` быстрее пошагового `FWHT`), равномерно размазывая выбросные каналы `o_proj` и `down_proj` (`+0.09..+0.20` эквивалентных бит на `o_proj`) при стоимости `O(K log K)` один раз на вектор активаций.
5. **Усовершенствованный энкодер без изменения декодера**:
   - Слитый C++/CUDA цикл обратного Холецкого `ldlq_block256_cuda` (`pp = 0..4`), рефит блочных экспонент `2^(0.25 · e)` (`e ∈ [-16, 15]`) и взвешенный по Фишеру рефит `(d_row, suh)`;
   - Адаптивное окно кандидатов динамического программирования `vtq2_candidates_for_target` (`[target - 0.45, 6.22]`) без низкопамятевых гауссовских ловушек;
   - Сквозной полиш масштабов `(d_row, suh)` по `KL` при замороженном дискретном LDLQ-треллисе (`End2End Frozen-LDLQ Scale Polish`: дополнительно **`-5%..-13%` KLD** за `12–30 с` при `0` доп. бит);
   - Выходно-взвешенный кольцевой квантователь **`VtqRing-OP`** для таблиц Per-Layer Embeddings (`Gemma 4 PLE`: **`-30%..-48%` KLD** при том же объёме файла и `0` доп. операций на инференсе).

## 2. Математическая модель реконструкции матрицы

Пусть линейный слой имеет матрицу весов $W \in \mathbb{R}^{M \times K}$, где $16 \mid M$ и $256 \mid K$. Реконструированная матрица $\widehat{W}$ задаётся формулой:

$$
\widehat{W}_{m, :} = \Bigl(\mathcal{R}_K^\top \bigl(\widetilde{W}_{m, :}\bigr)\Bigr) \odot \text{suh}, \qquad
\widetilde{W}_{m, 256 b + t} = d_{\text{row}}[m] \cdot 2^{0.25 \, e[m, b]} \cdot G_{m, 256 b + t},
$$

где:
- $b \in \{0, \dots, K/256 - 1\}$ — индекс `256`-элементного блока вдоль строки; $t \in \{0, \dots, 255\}$ — позиция внутри блока;
- $d_{\text{row}} \in \mathbb{F}_{16}^M$ — построчный масштаб (`fp16`);
- $e \in \mathbb{Z}_8^{M \times (K/256)}$ — знаковая целочисленная экспонента подблока (в диапазоне `[-16, 15]`, шаг $2^{0.25} \approx 1.1892$, динамический диапазон $2^{31/4} \approx 215\times$ внутри каждой строки);
- $\text{suh} \in \mathbb{F}_{16}^K$ — входной вектор предобусловливания со встроенными знаками Радемахера:
  $$\text{suh}_j \propto \operatorname{sign}_j \cdot \|W_{:, j}\|_{2, F}^{0.50} \cdot H_{jj}^{-0.25};$$
- $\mathcal{R}_K = H_{2^a} \otimes \operatorname{DCT\text{-}II}_q \in \mathbb{R}^{K \times K}$ — каноническое ортогональное преобразование ($\mathcal{R}_K^\top \mathcal{R}_K = I_K$). На инференсе вместо вращения весов достаточно один раз повернуть входной вектор активаций $x_{\text{rot}} = \mathcal{R}_K(x \odot \text{suh})$, после чего скалярное произведение вычисляется напрямую в сжатой области: $\langle \widehat{W}_{m,:}, x \rangle = \langle \widetilde{W}_{m,:}, x_{\text{rot}} \rangle$;
- $G \in \mathbb{R}^{M \times K}$ — матрица значений решёточно-кодированного квантователя (`TCQ`), разбитая по строкам на произвольное число полос смешанной точности `row_slices = [(r0, r1, fmt_idx, byte_off), ...]` (`16 \mid r_0, r_1`), а внутри каждой полосы — на двумерные тайлы **`16 × 16` (`TILE = 256` весов)**.

## 3. Устройство `16 × 16` тайла, треллиса и кодовых книг `uint8`

### 3.1. Замкнутый (tail-biting) треллис Унгербёка (`NU = 10`, `nl = 16`)
Тайл размера `16 × 16` обходится построчно в ленту длины $L = 256$ (для коротких кольцевых таблиц `VtqRing` поддерживается также $L = 160$). Последовательность кодовых битов $c_0, \dots, c_{L-1} \in \{0, 1\}$ образует циклическое 10-битное состояние сдвигового регистра:

$$
s_t = \sum_{j=0}^{9} c_{(t - j) \bmod L} \, 2^j \in \{0, \dots, 1023\}.
$$

Метка подмножества $\text{lab}_t \in \{0, \dots, 15\}$ (`nl = 16` косетов для всех форматов `VTQ v2`) вычисляется через чётность маскированных битов памяти с тройкой оптимальных масок `(359, 40, 475)`:

$$
\text{lab}_t = (s_t \mathbin{\&} 1) \;\Big|\; \bigoplus\bigl((s_t \gg 1) \mathbin{\&} 359\bigr) \ll 1 \;\Big|\; \bigoplus\bigl((s_t \gg 1) \mathbin{\&} 40\bigr) \ll 2 \;\Big|\; \bigoplus\bigl((s_t \gg 1) \mathbin{\&} 475\bigr) \ll 3.
$$

### 3.2. Пять 64-байтно выровненных битовых регионов полосы (`SoA`)
Для полосы из $T_n = \frac{R}{16} \cdot \frac{K}{16}$ тайлов функция `pack_slice` укладывает 5 последовательных массивов `uint16` слов (каждый выровнен на границу `64` байт):

| № | Регион | Слов `uint16` на тайл (`L=256`) | Назначение |
| :-: | :--- | :---: | :--- |
| 1 | `codes` | `16` (`32 B`) | Кодовый бит треллиса $c_t = \text{lab}_t \mathbin{\&} 1$ (`256` бит) |
| 2 | `usgn` | `16` (`32 B`) или `0` (`K=2, frac>0`) | Старший некодированный бит (знаковая полуось $u_{\text{sgn}} = (u_t \gg (K-2)) \mathbin{\&} 1$) |
| 3 | `umid` | $\max(K - 3, 0) \times 16$ | Промежуточные некодированные биты амплитуды (`K ≥ 4`: биты `1 .. K-3`) |
| 4 | `lsb` | `0 / 4 / 8 / 12 / 16` | Младший некодированный бит $u_t \mathbin{\&} 1$, сжатый режимом `frac` |
| 5 | `gains` | $\lceil \frac{256}{\text{sub}} \cdot h / 16 \rceil$ | Индексы усиления $g \in \{0, \dots, 2^h - 1\}$ на каждые `sub = 16` весов |

Режимы дробной скорости `frac` (`FRAC_NAMES = ["none", "d2", "d4", "d4_eq", "gosset84"]`) на плоскости `lsb`:
- `frac = 0` (`none`, скорость $K$): все `256` младших битов независимы (`16` слов при `K ≥ 3`; при `K = 2` единственный некодированный бит лежит в `usgn`);
- `frac = 1` (`d2`, скорость $K - 0.5$): парное равенство $\text{lsb}_{2i} = \text{lsb}_{2i+1}$ (`8` слов, сохраняется только как контрольный референс `VTQ150_D2`);
- `frac = 2` (`d4`, скорость $K - 0.25$): условие чётности четвёрки $\text{lsb}_{4i+3} = \text{lsb}_{4i} \oplus \text{lsb}_{4i+1} \oplus \text{lsb}_{4i+2}$ (`12` слов = `192` бита);
- `frac = 3` (`d4_eq`, скорость $K - 0.75$): равенство четвёрки $\text{lsb}_{4i..4i+3}$ (`4` слова = `64` бита);
- **`frac = 4` (`gosset84`, скорость $K - 0.5$, основной полуцелый режим VTQ v2)**: каждые 8 бит $\text{lsb}_{8i..8i+7}$ образуют одно из 16 кодовых слов расширенного кода Хэмминга `[8, 4, 4]` (двоичная проекция решётки Госсета $E_8$ с минимальным расстоянием Хэмминга $d_{\min} = 4$):
  ```text
  HAM_CW8[16] = {0x00, 0xFF, 0xF0, 0x0F, 0xCC, 0x33, 0x3C, 0xC3,
                 0xAA, 0x55, 0x5A, 0xA5, 0x66, 0x99, 0x96, 0x69}
  ```
  Хранится 4-битный индекс `idx4 ∈ [0..15]` (`8` слов = `16` байт на тайл).

### 3.3. Аппаратные `uint8` кодовые книги (`qmax = 128`)
Пусть $U = 2^{K-1}$, $U_+ = 2^{K-2}$ — число положительных уровней внутри одного подмножества. Таблица `lut[nl, U]` антиподально симметрична: для положительной половины $u_{\text{low}} \in \{0, \dots, U_+ - 1\}$ задаются беззнаковые целые уровни $q[\text{lab}, u_{\text{low}}] \in \{0, \dots, 128\}$ и скаляр `unit` (`fp32`), а отрицательная половина определяется отражением $\text{lut}[\text{lab}, :U_+] = -\text{lut}[\text{nl}-1-\text{lab}, U_+ - 1 : : -1]$:

1. **`type = "at"` (`K = 2, 3`)**: прямая таблица `mag_u8` размера `16` байт (`K = 2`, `1 × vpshufb`) или `32` байта (`K = 3`, `2 × vpshufb`).
2. **`type = "at2_16_16"` (`K = 4`)**: сумма двух 16-байтовых таблиц `TA_u8[16] + TB_u8[16]` (`32` байта суммарно, `2 × vpshufb + vpaddusb`, **`0` инструкций `vpblendvb`**):
   $$\text{idx}_A = u_{\text{low}} \mid ((\text{lab} \mathbin{\&} 3) \ll 2), \qquad \text{idx}_B = u_{\text{low}} \mid ((\text{lab} \gg 2) \ll 2).$$
3. **`type = "at2z_32_32"` (`K = 5, 6`)**: зонированная сумма двух 32-байтовых таблиц `TA_u8[32] + TB_u8[32]` с ограничением $\min(T_A + T_B, 128)$ (`4 × vpshufb` на `256` и `512` эффективных знаковых уровней при `K = 5` и `K = 6`).

## 5. Бинарный контейнер `.vtq` v2 (`VtqWriter` / `VtqFile`)

Структура файла `.vtq` v2 спроектирована под прямой `mmap` с выравниванием секции данных на страницу `4096` байт и всех тензоров — на кэш-линию `64` байта:

```text
+-----------------------------------------------------------------------+
| Offset 0..3   (4 B)  : MAGIC = b"VTQ\0"                               |
| Offset 4..7   (4 B)  : VERSION = uint32_le(2)                         |
| Offset 8..15  (8 B)  : H = uint64_le(header_reserve_bytes)            |
| Offset 16..16+H-1    : UTF-8 JSON-заголовок (дополнен пробелами 0x20) |
|                        Инвариант: (16 + H) % 4096 == 0                |
+-----------------------------------------------------------------------+
| Offset 16+H .. EOF   : Секция данных тензоров (64-byte aligned)       |
+-----------------------------------------------------------------------+
```

Для каждой квантованной матрицы `<prefix>` (например, `model.layers.0.mlp.down_proj`) записываются ровно 5 тензорных ключей:
1. `<prefix>.vtq.slices` — `i32 [S, 4]`: кортежи `[r0, r1, fmt_idx, byte_offset]` по полосам смешанной точности;
2. `<prefix>.vtq.data` — `u8 [N_bytes]`: конкатенация 64-байтно выровненных битовых регионов полос;
3. `<prefix>.vtq.d_row` — `f16 [M]`: построчные масштабы;
4. `<prefix>.vtq.e` — `i8 [M, K / 256]`: подблочные экспоненты с шагом `0.25` в $\log_2$;
5. `<prefix>.vtq.suh` — `f16 [K]`: входной вектор предобусловливания под кронекеровское вращение $\mathcal{R}_K$ (`quantization.rot_block = -1`).

**Проверка на полной модели**: упаковка всех `196` линейных матриц `Llama-3.2-3B-Instruct @ 3.0000 bpw` в файл объёмом `1.070 ГБ`, обнуление весов в памяти и повторная загрузка через `VtqFile.decode_matrix` показали **`0.000000` дрейфа KLD** (`0.041033 / 0.053821` до и после сериализации).

## 7. Алгоритмические исследования энкодера (`Exp06` и `Exp07`)

### 7.1. Проверка `MACaQ` и `TVQ` против `End2End Frozen-LDLQ Scale Polish` (`Exp06`, [`results/exp06_macaq_and_tvq.json`](../../results/exp06_macaq_and_tvq.json))
На идентичном бинарном формате `.vtq` v2 (`0` лишних бит, `0` изменений декодера) были проверены две идеи из свежей литературы против нашей схемы сквозного полиша масштабов:
1. **`MACaQ-VTQ2`** (мульти-экспонентные предложения внутри LDLQ + блочный координатный спуск валидных `16×16` тайлов по полному офф-диагональному гессиану $H$): на реальных матрицах `Qwen3-8B` даёт лишь `+0.0002..+0.0011` бит на отложенном $H_e$, а на полной `Llama-3.2-3B` статистически неотличим от базы (`+0.05%..+1.5%` KLD) при `2–4×` росте времени квантования. Причина: в отличие от диагональных `GGUF IQ3_XXS`, в `VTQ v2` каузальный `ldlq_block256_cuda` уже учитывает полный обратный Холецкий $H^{-1}$ непосредственно при выборе пути Витерби.
2. **`TVQ-Block`** (`arXiv:2610.41822`, поблочная STE-дистилляция латентных весов трансформерного блока с периодическим перекодированием через `viterbi_ub_cuda`): на `2.0 bpw` даёт `-0.64% / +0.56%` (шум), а на `2.5 bpw Gosset84` валидационный фильтр отклоняет `28/28` перекодированных слоёв, поскольку диагональное перекодирование мгновенно разрушает офф-диагональную LDLQ-компенсацию межстолбцовых корреляций.
3. **`VTQ2-End2End-Polish` (победитель)**: заморозка дискретного LDLQ-треллиса $G$ (сохраняющая 100% корреляционной компенсации Холецкого) и быстрая сквозная оптимизация непрерывных `fp16` векторов `(d_row, suh)` по финальной `KL`-дивергенции всей модели одновременно снижают KLD на **`-8.86% / -7.19%` при `2.0 bpw` (`+16.3 с`)**, **`-4.83% / -3.51%` при `2.5 bpw` (`+12.3 с`)** на `3B` и **`-12.94% / -10.57%` при `2.5 bpw` (`+30.5 с`)** на `Qwen3-8B` (`p = 1.0000` везде).

### 7.2. Находка по `GPTAQ` на широких моделях с `QK-Norm` (`8B+`)
- На компактных моделях (`Llama-3.2-1B`, `Llama-3.2-3B`, `K_down = 8192`, без `QK-Norm`) асимметричная компенсация потока `GPTAQ` ($\alpha = 0.50$, $W_{\text{target}} = W + \alpha W B^\top$) стабильно даёт **`-8%..-12%` KLD** (`p = 1.0000`).
- На широких глубоких моделях с `QK-Norm` (`Qwen3-8B`, `36` слоёв, `K_down = 12288`) матрица кросс-ковариации $B \in \mathbb{R}^{12288 \times 12288}$ насчитывает `151 млн` свободных параметров при `131 тыс.` калибровочных токенов (`N/K = 10.7`), переобучаясь на угловой дрейф после по-головной нормализации запросов/ключей (`+13.1% / +19.6%` хуже на отложенных трассах). Поэтому для широких/гибридных моделей (`8B+`, `Qwen3.5`, `Gemma 4`, `30B MoE`) в `VTQ v2` используется режим **`gptaq_alpha = 0.0`** + `End2End Frozen-LDLQ Scale Polish`.
